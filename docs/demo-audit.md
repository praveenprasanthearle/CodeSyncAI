# Public demo audit and interview notes

Audited 19 October 2026 against `1e604509095057a47bfcc603b75a255c38b65c33` on branch `fix/public-demo-ai-reliability`.

## The five blockers, in priority order

| Priority | Finding and evidence | Implemented change |
| --- | --- | --- |
| 1 | Anonymous `/execution/run` requests ran host processes. A benign probe confirmed that executed code could see the repository outside its temporary directory. Timeouts and environment filtering did not provide filesystem isolation. | Require authentication, per-user rate limits and bounded execution slots/output. Production rejects local execution and uses a Docker runner without host mounts/network, with resource limits and a non-root user. Remove simulated C/Python/Rust execution; report missing toolchains. Transpile TypeScript before running it. |
| 2 | Socket handlers trusted project/file identifiers without checking membership or editor roles. Individual snapshot reads/restores also lacked project checks. Populated project references could produce an incorrect user role. | Check roles for socket, file, chat and voice actions. Evict removed members. Restrict voice signaling to the same room. Authorize snapshot reads/restores/deletes. Normalize populated reference IDs. |
| 3 | An email-writing prompt returned a generic C program. Provider failures silently became canned answers. The model chain started with retired Gemini 2.0, ignored conversation history and fabricated code-action metadata. | Use real Gemini and OpenAI provider calls, configurable models, a general-purpose prompt, bounded history, structured action validation, explicit errors, connection verification and per-user limits. Add readable Markdown/math, multiline prompts, retry/cancel and tab-scoped keys. |
| 4 | The browser sent CRDT updates and whole-file replacements. First-join initialization could race, snapshots read before persistence, restores replaced file IDs, and cloning omitted files. Two-browser testing also exposed a race from React's controlled editor value. | Use `MonacoBinding` and let Yjs own editor text. Never echo remote updates or send parallel full-text replacements. Share initialization promises, serialize writes, flush before capture, preserve IDs on restore, reject stale REST saves, copy files during cloning and escape literal folder paths. Bundle Monaco workers locally. |
| 5 | Parallel 401s refreshed separately, failed auth requests could trigger refresh again, restored state could retain an expired token, and reconnects could create duplicate sockets or use stale credentials. Setup/deployment also used shared example secrets and exposed MongoDB. | Share one refresh promise, exclude auth endpoints, synchronize token state, reuse sockets and resynchronize documents on reconnect. Generate unique setup secrets, use the same-origin proxy, fail startup/health checks on unavailable storage, remove published DB/API ports and require deployment secrets. |

## Verification

The original TypeScript/production build passed. After adapting MongoDB to use TCP-only sockets in this environment, the original backend suite had 70 passes and one voice-test timeout; the 16 frontend tests passed. Legacy socket tests relied on connection timing and sometimes left sockets open on failure. Their replacements wait for acknowledgements and clean up clients deterministically.

Final validation is recorded after the clean dependency installation:

- Automated tests: **137 total** — 105 backend and 32 frontend.
- TypeScript and Vite production build.
- Eight browser workflow checks with two separate browser sessions and no page runtime errors.
- Production dependency audit: **zero reported vulnerabilities** after the clean root-lockfile installation. This is a dependency advisory check, not a claim that the application has no security defects.

The browser test performs:

1. Register an owner and load the dashboard.
2. Create a project, load bundled Monaco, edit a C file and confirm persisted content.
3. Run C through the UI and verify actual native stdout.
4. Register/invite an editor and verify concurrent edits in both browsers and MongoDB.
5. Deliver a team-chat message to the second account.
6. Capture recent edits, change the file, restore the snapshot and update both live editors.
7. Replace the access token with an expired token and recover using the HttpOnly refresh cookie.
8. Verify honest missing-key chat behavior and the AI provider settings UI.

Screenshots and machine-readable results are generated by `npm run test:e2e` under `test-results/demo-smoke` and are intentionally excluded from Git.

## What remains unverified

- **Live AI answers:** no valid Gemini/OpenAI credential was available. Provider contract/error handling was tested using controlled responses. Run `npm run check:ai` after configuring a key; the check covers a general writing request and follow-up recall.
- **Production Docker execution:** this environment has no Docker daemon. The runner implementation and production guard are present; native execution, timeout, output limiting and the fail-closed guard were tested. Build the image and verify Docker mode on the intended runner host before enabling it publicly.
- **Voice media across networks:** signaling was integration tested; real microphone/audio, TURN and NAT traversal were not validated.
- **Hosted deployment and load:** no public hosting, load test or high-availability claim is made. The development embedded database is disposable. Snapshot restoration uses multiple database writes, not a cross-document transaction.

The production build includes a sizable lazy workspace/Monaco chunk. The landing/dashboard bundle does not load it immediately, but the first workspace visit still downloads the editor and language workers.

The full development dependency audit still reports 11 advisories (3 moderate, 6 high, 2 critical) in the test/watch/CSS toolchain, including Vitest/Tinypool and Tailwind's dependency chain. They are excluded from the production dependency audit. Resolving those requires separate toolchain upgrades; they were not hidden with audit exclusions or automatic breaking upgrades.

## Interview answers you can defend

### “Did you train the AI?”

“No. The assistant integrates Gemini or OpenAI through server-side provider APIs. My work covers conversation state, editor context, prompt design, authentication, key handling, structured responses, failure handling and the chat interface. I verify provider integration separately from answer quality.”

### “Why did the previous assistant return unrelated code?”

“It substituted keyword templates whenever the provider was absent or failed. That hid configuration failures behind HTTP success. I removed that fallback. Missing keys, invalid credentials, quota exhaustion, unavailable models, timeouts and malformed output now have distinct errors.”

### “How does simultaneous editing avoid lost updates?”

“MonacoBinding converts editor changes into operations on Y.Text. Socket.IO carries incremental Yjs updates, and remote updates have a remote origin so they are not echoed. I removed competing whole-file replacements and React-controlled editor writes. I verified convergence using two independent browser sessions.”

### “Why are snapshots related to collaboration?”

“Live edits may exist in memory before the debounce timer saves them. Capturing only MongoDB would miss recent changes, so capture first flushes pending writes. Restore retains matching file IDs and updates the existing Yjs document, allowing connected peers to receive the same replacement.”

### “What makes code execution isolated?”

“Local development execution is not an isolation boundary. Production refuses that mode. The Docker path uses a separate container for each run, no host mounts or network, a read-only root filesystem, a non-root user, dropped capabilities and CPU, memory, process, output and elapsed-time limits. The actual Docker deployment still needs validation on its host.”

### “How did you prevent refresh-token bugs?”

“All simultaneous expired requests share one refresh operation. Login and refresh failures do not recursively refresh. The new token updates both storage and application state, and socket authentication reads the current token. The browser test forces an expired token and verifies that the workspace recovers.”

### “Can it do everything ChatGPT does?”

“It supports general text conversations and programming assistance through the selected model, with active editor context when requested. It does not currently have browsing, image generation, repository retrieval/RAG or autonomous execution tools. I describe those boundaries rather than claim complete parity.”

## Reproduce the checks

```bash
npm ci
npm run setup
npm test
npm run build
npm audit --omit=dev
npx playwright install chromium
npm run test:e2e
```

For a real provider check, put a valid key in `backend/.env` and run `npm run check:ai`. Alternatively, use the app's AI Settings to verify a tab-scoped key. Do not commit provider keys or put them in frontend build variables.
